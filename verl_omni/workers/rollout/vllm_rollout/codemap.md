# verl_omni/workers/rollout/vllm_rollout/

## Responsibility
The vLLM-Omni rollout implementation: an HTTP server ray actor (`vLLMOmniHttpServer`) and replica wrapper (`vLLMOmniReplica`) that run vLLM-Omni's `AsyncOmni` engine in two modes — diffusion (image/video/audio generation with trajectory latents/log-probs) and AR (autoregressive omni text) — plus colocated worker extensions for sleep/wake and trainer→rollout weight sync over ZMQ IPC.

## Design
- `vllm_omni_async_server.py` (mode split driven by `engine_kwargs.vllm_omni.output_mode`: `"diffusion"` default vs `"ar"`):
  - `vLLMOmniHttpServer(vLLMHttpServer)` — hook-based subclass: `_init_config`/`_init_model_config` pick `DiffusionRolloutConfig`/`DiffusionModelConfig` vs `RolloutConfig`/`OmniModelConfig`; `_get_engine_kwargs_key()="vllm_omni"`; `_preprocess_engine_kwargs` (AR: writes a deploy config YAML from the pipeline adapter's stage topology via `_write_deploy_config`, merges `hf_overrides`, normalizes dash keys; diffusion: registers custom pipeline from `VllmOmniPipelineBase`, clamps `max_num_seqs=1` for non-request-batched pipelines, prompt-embed cache args).
  - `run_server(args)` builds `OmniEngineArgs` → `AsyncOmni` engine client → `build_app` + `omni_init_app_state` → `run_uvicorn`. Sets `MASTER_ADDR/PORT` for vLLM-Omni workers; applies `rollout_attn_backend` via `diffusion_attention_config`.
  - Sleep/wake: `_get_wake_up_tags()=["weights"]`, `_resolve_sleep_level()=1` (level-2 would discard non-actor pipeline weights like text encoder/VAE); `wake_up` uses `engine.collective_rpc("wake_up")` (avoids CUDA init in server process); `_sleep_hybrid` also calls `reset_encoder_cache`.
  - Generate pipeline: `generate(...)` → `_resolve_lora_request` (cached per weight version behind an asyncio lock, since `list_loras` is a busy-loop RPC) → `_preprocess_input` (AR: `SamplingParams` with max_tokens clamping and logprobs normalization; diffusion: `OmniCustomPrompt` + `OmniDiffusionSamplingParams`, negative/extra prompt ids for multi-encoder models) → `_run_generation` (`engine.generate`, async iterate to final `OmniRequestOutput`) → `_process_output` (AR: `TokenOutput`; diffusion: `DiffusionOutput` with uint8 pixels or latents, `trajectory_log_probs`, `extra_fields` from `trajectory_latents/timesteps` + `multimodal_output["metadata"]["prompt_embeddings"/"rl"]`).
  - Abort: `abort_all_requests`/`abort_request` override AsyncLLM-specific parent (AsyncOmni routes via an Orchestrator, no `output_processor`): phase-1 natural drain with timeout (`VERL_OMNI_ABORT_DRAIN_TIMEOUT_S`, default 120s), phase-2 `engine.abort` + `_enqueue_abort_output` synthesizes a terminal abort `OutputMessage` into each request queue to unblock `generate()`.
  - `vLLMOmniReplica(vLLMReplica)` — ray wrapper, `server_class = ray.remote(vLLMOmniHttpServer)`, name prefix `vllm_omni_`.
- `utils.py`: `vLLMOmniColocateWorkerExtension(CustomPipelineWorkerExtension)` — worker-side weight sync: `update_weights_from_ipc(peft_config, base_sync_done, use_shm, zmq_update_id)` uses `BucketedWeightReceiver`; LoRA path removes the old adapter then one atomic `add_lora` with `TensorLoRARequest` (standard vLLM AR) or `OmniTensorLoRARequest` (diffusion); full-weight path streams buckets through `model.load_weights` (+`process_weights_after_loading`, Ascend MoE `patch_vllm_moe_model_weight_loader`) or `pipeline.load_weights`. `set_pending_lora_peft_config` stashes the peft_config for the standalone NCCL path. ZMQ handle = `ipc:///tmp/rl-colocate-zmq-<job>-replica-<r>-rank-<k>.sock`.
- `npu_utils.py`: `vLLMOmniNPUColocateWorkerExtension` — Ascend overrides guarded by `_is_npu_platform()`: `CaMemAllocator` memory-pool contexts, `sleep`/`wake_up` with buffer snapshots, `_skip_diffusers_npu_empty_cache` monkeypatch (NPU empty-cache corrupts pool bookkeeping).
- `zmq_utils.py`: `make_update_zmq_id` / `make_update_zmq_handle` — per-update unique IPC endpoints (`...-update-step-<n>-seq-<k>.sock`) so one-sender/one-receiver routes never collide.

## Flow (weight sync, colocated)
1. `ActorRolloutRefWorker.update_weights` puts rollout to `sleep_level=1`, gathers params via `engine.get_per_tensor_param` and calls `rollout.update_weights(per_tensor_param, peft_config, base_sync_done, global_steps)`.
2. Server fans out to workers via `collective_rpc("update_weights_from_ipc", ...)`; each worker builds a `BucketedWeightReceiver` on `make_update_zmq_handle(base, update_id)` and loads buckets (LoRA atomic `add_lora`, full weights streamed).
3. Steady-state LoRA fast path: `BucketedWeightSender` in `engine_workers` sends adapter-only weights over ZMQ IPC; `set_global_steps`/sleep/wake invalidate the server's `_lora_request_cache`.
4. Standalone-async: `OmniCheckpointEngineManager` pushes `peft_config` via `collective_rpc("set_pending_lora_peft_config")`, then NCCL broadcast; workers consume the stash inside `update_weights_from_ipc`.

## Integration
- Consumed by: `verl_omni/workers/rollout/replica.py` (replica registry), verl's `ServerAdapter`, `ActorRolloutRefWorker`, `OmniCheckpointEngineManager`.
- Depends on: `vllm_omni` (`AsyncOmni`, `OmniEngineArgs`, `OmniCustomPrompt`, `OmniDiffusionSamplingParams`, `LoRARequest`, `OmniRequestOutput`, `CustomPipelineWorkerExtension`), `verl.workers.rollout.vllm_rollout` (`vLLMHttpServer`, `vLLMReplica`, `BucketedWeightSender/Receiver`, `VLLM_LORA_*` constants), `verl_omni.utils.vllm_omni` (`VLLMOmniHijack`, `OmniTensorLoRARequest`), `verl_omni.pipelines.model_base` (`VllmOmniPipelineBase`, `OmniRolloutPipelineBase`).
- Key entry points: `vLLMOmniHttpServer.generate`, `vLLMOmniReplica`, `vLLMOmniColocateWorkerExtension.update_weights_from_ipc`, `vLLMOmniNPUColocateWorkerExtension`.
